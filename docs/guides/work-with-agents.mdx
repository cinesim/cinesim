title: Work with an agent
description: Connect Claude Code or Codex to inspect, author, compile, and revise one local Cinesim project.

Cinesim is a direct-file agent workflow. People, internal sessions, Claude Code, and Codex all author
the same canonical project: `cinesim.toml`, `assets.toml`, and the reachable `.js`/`.jsx` video source
modules. MCP supplies inspection, perception, diagnostics, and disposable services; it does not
contain a second editing API.

## Set up a provider

Open **Settings → Agents**. Cinesim discovers installed Claude Code and Codex executables and shows
their login status. Choose an executable, model, reasoning effort, and permission mode.

Each new or opened project receives deterministic integration files:

- `AGENTS.md` contains Cinesim's managed guidance plus your custom default instructions;
- `CLAUDE.md` imports that same guidance;
- `.mcp.json` and `.codex/config.toml` merge a Cinesim-owned `cinesim mcp --project .` entry without
  overwriting unrelated provider settings.

The generated files contain no bearer token, transient port, account secret, or machine-specific
application state. Provider trust and approval prompts remain visible.

## Choose a permission mode

| Mode                               | Behavior                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Supervised**                     | The provider asks before file or shell operations that require approval.                          |
| **Automatic workspace operations** | The provider may perform allowed project-local file and shell work without per-operation prompts. |

Both modes start in the project root and use the provider's normal project-scoped safety boundary.
They do not change compiler validation or grant an MCP canonical-write path.

## Start with context

Open the agents sidebar in Media, Cut, or Edit. A turn receives the project directory, accepted
generation, candidate compiler state, active composition and playhead, selected assets and clips,
and bounded diagnostics. Ask for outcomes that are inspectable in source and in the editor:

- "Inspect the selected interviews and propose a two-minute dialogue assembly."
- "Build a J-cut into the second answer and preserve the linked A/V relationship."
- "Add scene and continuity notes, then sample the accepted timeline and revise weak cutaways."

Project `AGENTS.md` is the standing source of behavioral guidance for internal and external agents.

## Use the perception loop flexibly

There is no mandatory call sequence, but dependable assembly usually repeats this loop:

1. Inspect `project_status`, assets, accepted timeline structure, and language capabilities.
2. Check transcript and visual-index coverage; start or regenerate missing disposable work when it
   would improve the decision.
3. Read a bounded transcript range, fetch visual observations, and request low/medium/high frames
   for the same source interval when evidence is needed. After acceptance, request timeline frames
   by sequence ID to inspect the actual WebGPU-composited result.
4. Edit canonical TOML or JSX directly: assemble clips, supporting picture/audio, structured notes,
   split edits, and supported finishing constructs.
5. Wait for a successful compiler acceptance. If the disk candidate is invalid, use its precise
   diagnostics without treating it as the live editor state.
6. Inspect the projected timeline transcript, visual structure, or timeline samples and revise the
   source again.

The visual index under `.video/visual-index` is reusable but disposable perception. Correcting,
splitting, merging, clearing, or regenerating it does not compile the project or enter undo history.
Generation samples at most 180 decoded frames in a dedicated low-priority worker and records only
conservative pixel evidence: brightness, colorfulness, and visual change. It deliberately does not
invent people, objects, dialogue, or story meaning. Use `visual_index_upsert` to add or correct
semantic observations when stronger evidence is available.
Deliberate story intent belongs in canonical project, asset, or timeline notes instead.

## Acceptance, history, and review

The editor keeps playing the last accepted generation while an incomplete or invalid save is on
disk. Each quiet, valid, deduplicated canonical generation becomes the next accepted state and an
ordinary top-bar undo step, regardless of whether it came from the UI, an internal agent, or an
external editor. Undo and redo atomically restore the complete canonical file set and survive a
project reopen through bounded `.video/history` snapshots.

Review the agent's source diff, compiler state, and resulting timeline. There is no chat-specific
restore control or competing history model.

## Safety boundaries

- Do not hand-edit generated `.video/` artifacts; use the relevant MCP or UI service.
- Do not modify or delete source media as an editing operation.
- Do not treat a compiler-accepted construct as preview/export support; inspect capability state.
- Do not add secrets or transient broker credentials to project configuration.
