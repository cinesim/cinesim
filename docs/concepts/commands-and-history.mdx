---
title: Compile acceptance and history
description: UI commands and direct source edits converge on one accepted project history.
---

Cinesim has one acceptance boundary with two deliberate authoring inputs. Desktop gestures and CLI
operations submit validated semantic commands. People, coding agents, and text editors may directly
edit `cinesim.toml`, `assets.toml`, and reachable JavaScript/JSX source. Both paths must produce a
fully parsed, bound, validated, compiled canonical generation before the editor accepts them.

MCP is not a third authoring path. It provides project/language inspection, transcripts, exact
frames, the disposable visual index, and export services, but exposes no canonical mutation tool.

## One pathway

A command is validated before anything is written. It checks IDs exist, that a placement is
compatible with its track, that timing is in range, and that project rules hold. Invalid commands
fail with a structured error and change nothing.

Direct saves are watched as debounced complete generations. A valid generation becomes live and
appears in the same history as a UI command. An invalid candidate remains on disk for repair while
preview, inspection, exact-frame sampling, and export retain the last accepted IR and expose bounded
candidate diagnostics. There is no agent-only format, history, or restore control.

## One gesture, one undo step

While you drag or trim, Cinesim shows an ephemeral preview. Nothing is committed until you release.

So a completed drag becomes a single command in history, not a trail of pointer updates. Undo takes
you back to the state before the gesture, which is what you actually want. Panel resizes and
selection changes never enter history at all — they are interface state, not project state.

Undo and redo restore bounded, content-deduplicated snapshots of the full canonical file set. The
journal survives reopen. Guidance/provider files and everything under `.video/` are deliberately
outside project history.

## Safe by default on removal

Destructive commands carry extra conditions, chosen so that the dangerous version of an action is
never the default:

- A track must be unlocked and empty before it can be removed.
- Deleting an asset removes the clips that reference it, but never touches the source file on disk.
- The last sequence in a project cannot be deleted.
- A clip on a locked track blocks operations that would modify it.

## Determinism

Canonical serializer output is deterministic: unordered collections sorted, track order preserved,
integers rather than floats, pretty printing, explicit versions, and no timestamps. UI/CLI writes
use a project-scoped lock, revision checks, journaled temporary files, and atomic publication, so a
crash or stale writer cannot silently overwrite a newer generation.

Unknown schema versions are rejected outright rather than opened optimistically. A project written
by a future version of Cinesim will refuse to load until a migration exists.
