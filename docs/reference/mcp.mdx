title: MCP reference
description: Inspection, perception, diagnostics, and disposable services exposed to coding agents.

Cinesim's MCP server helps agents understand an accepted project and invoke bounded local services.
It has no canonical editing tools. Agents author `cinesim.toml`, `assets.toml`, and reachable JSX
directly; the compiler validates each candidate before it becomes the accepted editor generation and
an ordinary top-bar undo step.

For project-local setup, see [Work with an agent](../guides/work-with-agents.mdx).

## Transport and scope

Generated Claude and Codex project configuration launches the packaged stdio adapter in the project
root:

```bash
cinesim mcp --project .
```

When the project is open, that adapter discovers the desktop's mode-`0600`, bearer-authenticated
loopback broker descriptor. Credentials remain transient and never enter generated provider config.
Without a live desktop it falls back to read-only disk inspection and does not create `.video/`.

All times are integer microseconds. Results are bounded structured content. Canonical IDs are stable
prefixed strings such as `asset_…`, `clip_…`, `track_…`, and `sequence_…`.

## Project and language inspection

| Tool               | Purpose                                                                                                               |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `project_inspect`  | Accepted identity, directory, revision, and timeline counts                                                           |
| `project_status`   | Accepted generation, candidate validity, bounded diagnostics, last valid composition, jobs, and visual-index coverage |
| `assets_list`      | Canonical asset references and technical metadata                                                                     |
| `asset_inspect`    | One asset by stable ID                                                                                                |
| `timeline_inspect` | Accepted tracks, clips, links, and exact timing                                                                       |
| `notes_inspect`    | Structured project, asset, and timeline notes                                                                         |
| `language_search`  | Fuzzy syntax, constraints, examples, recipes, and separate compiler/preview/export capability states                  |

`language_search` classifies results as nodes, typed properties, effects, blend modes, animations,
transitions, or recipes. Property rows include types, required/animatable constraints, options, and
their own compiler/preview/export state. Blend-mode, easing, picture-transition, and audio-crossfade
values are independently searchable, so compiler acceptance is never used as a proxy for rendered
support. Results are deterministically ranked and capped at 20.

## Transcripts

| Tool                      | Purpose                                                             |
| ------------------------- | ------------------------------------------------------------------- |
| `transcript_get`          | Bounded asset transcript range; may resolve a visual observation ID |
| `timeline_transcript_get` | Bounded dialogue projected through accepted clip timing             |
| `transcript_generate`     | Start missing disposable transcript jobs                            |
| `transcript_regenerate`   | Force fresh disposable transcript jobs                              |
| `transcript_cancel`       | Cancel active transcript jobs                                       |

Transcript jobs change derived state only. They never compile or enter canonical history.

## Visual index

| Tool                      | Purpose                                                       |
| ------------------------- | ------------------------------------------------------------- |
| `visual_index_status`     | Coverage, freshness, source fingerprints, and compatibility   |
| `visual_index_get`        | Bounded timestamped observations for one asset/range          |
| `visual_index_generate`   | Run bounded local analysis when compatible evidence is absent |
| `visual_index_regenerate` | Replace observations with a fresh bounded local analysis      |
| `visual_index_upsert`     | Add or correct validated timestamped observations             |
| `visual_index_delete`     | Remove selected observation IDs or a bounded range            |
| `visual_index_clear`      | Remove selected assets' disposable index artifacts            |

Visual-index mutations are intentionally allowed because `.video/visual-index` is disposable. They
do not edit source, compile the project, or affect undo history. Generation requires the live
desktop renderer, processes at most eight requested assets sequentially, samples at most 180 frames
per asset, and yields to active playback, seeking, dragging, and hover skimming. Its automatic
descriptions cover measurable light, color, and visual-change evidence only; semantic corrections
belong in validated `visual_index_upsert` observations.

## Media artifacts

| Tool            | Purpose                                                                                                |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| `filmstrip_get` | Report the bounded derived contact-sheet artifact for an asset                                         |
| `frame_get`     | Generate or reuse an exact asset, observation-midpoint, or accepted-timeline frame and return its path |

`frame_get` accepts exactly one of `assetId` or `sequenceId`, an integer `atUs` (or an observation
ID for an asset), and `low`, `medium`, or `high` quality. Requested times normalize to the exact
source or composition frame. The quality tiers cap the long edge at 640, 1280, and 1920 pixels;
the service returns requested, normalized, and rendered timestamps, dimensions, byte size, and
stable PNG/metadata paths under `.video/frames/`. Asset samples decode through bounded
Mediabunny/WebCodecs work. Timeline samples use the accepted IR and normal WebGPU playback
compositor. A desktop-closed adapter can report an already cached frame but cannot generate one.
Generated frames are disposable, fingerprinted, capped at 16 MiB, and absent from canonical
history.

## Export services

| Tool                  | Purpose                                                                 |
| --------------------- | ----------------------------------------------------------------------- |
| `export_capabilities` | List deterministic SDR presets and whether a live renderer is available |
| `export_start`        | Start one accepted-IR timeline or range export                          |
| `export_status`       | Inspect bounded progress, failures, byte size, and artifact paths       |
| `export_cancel`       | Cancel the active job and remove its unpublished partial file           |

The first two presets produce H.264/AAC Rec.709 SDR MP4 at either a 1920-pixel maximum long edge or
the source composition size. The live renderer evaluates exact composition frame times through the
same WebGPU graph used by preview and timeline `frame_get`; audio uses the same clip ranges, fades,
gain, pan, transitions, and ducking automation. One export runs at a time. Chunks are bounded,
validated, and atomically published under `.video/exports/`; these files remain derived artifacts,
so copying a completed deliverable elsewhere is an explicit user-visible step. The disk-only MCP
fallback can inspect capabilities and status but cannot encode or cancel a renderer job.

## What is not exposed

There are no MCP tools for canonical asset deletion, source patches, timelines, tracks, clips,
properties, notes, captions, transitions, effects, keyframes, or batch edits. MCP cannot bypass the
compiler or restore history. Use ordinary file tools to edit canonical sources, then inspect
`project_status` for precise acceptance or candidate diagnostics.
